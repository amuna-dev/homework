# Homework #40 — Авторизация на JWT

Сайт с JWT-авторизацией: есть страница входа, защищённая страница профиля и выход.
Профиль запрашивается с токеном в заголовке `Authorization: Bearer <token>`.

- Сервер: <https://dummyjson.com>
- Тестовый аккаунт: **emilys / emilyspass**

## Как запустить

1. Открыть папку в VS Code.
2. Открыть `login.html` и нажать **Go Live** (расширение Live Server). Страница откроется по адресу `http://127.0.0.1:5501/login.html`, порт задан в `.vscode/settings.json`.

Можно открыть `login.html` и двойным кликом, но через локальный сервер надёжнее: `localStorage` у `file://` в разных браузерах работает по-разному.

### Деплой на Netlify

Сборка не нужна, это обычные статические файлы.
- **Build command:** пусто
- **Publish directory:** `.` (корень репозитория)

Главная страница сайта (`/`) открывает `index.html`, а он перенаправляет на `login.html`.

## Структура

```
index.html      — главная: сразу перенаправляет на login.html
login.html      — страница входа
profile.html    — защищённая страница профиля
css/style.css   — стили
img/avatar-placeholder.svg — заглушка, если фото не загрузилось
js/auth.js      — общие функции: сохранить, получить и удалить токены
js/login.js     — логика входа (задачи 1–2)
js/profile.js   — профиль, обработка 401, refresh и выход (задачи 3–5)
README.md       — этот файл и ответы на вопросы (задача 6)
```

## Что сделано

### Задача 1. Страница входа (`login.html`)
- Поля «Логин» и «Пароль», кнопка «Войти».
- Если поле пустое, под ним появляется ошибка («Введите логин» / «Введите пароль»), и запрос не отправляется.
- Запрос `POST https://dummyjson.com/auth/login` с телом `{ username, password }`.
- Пока идёт запрос, кнопка заблокирована и показывает текст «Вход...».
- При неверных данных выводится сообщение **«Неверный логин или пароль»**. dummyjson в этом случае отвечает `400 { "message": "Invalid credentials" }`, поэтому обрабатываются коды 400 и 401.

### Задача 2. Сохранение токена
- Из ответа берутся `accessToken` и `refreshToken` и сохраняются в `localStorage`.
- После успешного входа происходит переход на `profile.html`.
- Если пользователь уже вошёл и открыл `login.html`, его сразу перенаправляет на `profile.html`.

### Задача 3. Страница профиля (`profile.html`)
- При открытии проверяется наличие токена. Если токена нет, происходит перенаправление на `login.html`.
- Запрос:
  ```js
  axios.get('https://dummyjson.com/auth/me', {
    headers: { Authorization: 'Bearer ' + token }
  })
  ```
- На странице показываются фото, имя и фамилия, email, возраст и город. Если фото не загрузилось, вместо него показывается заглушка.
- Пока данные грузятся, отображается «Загрузка...».
- Если нет интернета, показывается сообщение и кнопка «Повторить». Токены при этом не удаляются.

### Задача 4. Ошибка 401 и выход
- Если сервер вернул 401, токены удаляются из `localStorage`, и пользователь попадает на `login.html`.
- Кнопка «Выйти» удаляет токены и возвращает на страницу входа. Если в этот момент ещё идёт запрос обновления токена, его ответ уже не запишет токены обратно.
- Особенность dummyjson: на испорченный вручную токен сервер часто отвечает не 401, а **500**. Сообщения при этом разные: `"invalid signature"` (символы дописаны в конец), `"invalid token"` (испорчено начало), `"jwt signature is required"`, а если поменять символ в середине, то даже ошибка разбора JSON. Поэтому ответ 500 от `/auth/me` тоже считается ошибкой токена, иначе ручная проверка из задания срабатывала бы не всегда.

### Задача 5 ⭐. Refresh
- При 401 сначала отправляется `POST https://dummyjson.com/auth/refresh` с `{ refreshToken }`.
- Если обновление удалось, новые токены сохраняются, и запрос профиля повторяется.
- Если не удалось, происходит выход на страницу входа.
- Проверено на настоящем истечении токена: токен на 1 минуту, через 75 секунд `/auth/me` отвечает `401 "Token Expired!"`, `/auth/refresh` выдаёт новую пару, повторный запрос профиля возвращает 200. Обычный access-токен dummyjson живёт 60 минут, так что вживую быстрее проверять порчей токена (см. ниже).

## Как проверить вручную

1. Войти как `emilys / emilyspass`, откроется профиль.
2. DevTools → Application → Local Storage: там лежат `accessToken` и `refreshToken`.
3. DevTools → Network → запрос `me`: в заголовках есть `Authorization: Bearer eyJ...`.
4. **Проверка refresh:** испортить только `accessToken` и обновить страницу. Сработает refresh, токены в Local Storage заменятся на новые, профиль загрузится.
5. **Проверка выхода по 401:** испортить **оба** токена (`accessToken` и `refreshToken`) и обновить страницу. Refresh не сработает, токены удалятся, откроется страница входа.
   Пока работает refresh, испорченный только access-токен восстанавливается автоматически. Так и задумано в задаче 5.
6. Удалить токены и открыть `profile.html`: сразу откроется `login.html`.
7. Нажать «Выйти»: токены удалятся, откроется страница входа.

> При обычной работе (вход → профиль → выход) консоль чистая. При вводе неверного пароля или при проверке с испорченным токеном браузер сам пишет строку о неуспешном сетевом запросе, например `Failed to load resource: ... 401`. Это лог браузера об ответе сервера (400 / 401 / 403 / 500), а не ошибка JavaScript. Все такие ответы код обрабатывает, и убрать эти строки из JS нельзя.

## Задача 6. Ответы на вопросы

### 1. Из каких трёх частей состоит JWT и что хранится в каждой

JWT — это строка из трёх частей, которые разделены точками:

```
xxxxx.yyyyy.zzzzz
header.payload.signature
```

Первые две части — это JSON, закодированный в **Base64URL** (это кодирование, а не шифрование).

1. **Header (заголовок)** — тип токена и алгоритм подписи.
   Пример из токена dummyjson:
   ```json
   { "alg": "HS256", "typ": "JWT" }
   ```

2. **Payload (полезная нагрузка)** — «claims», то есть данные о пользователе и о самом токене.
   Пример из токена dummyjson:
   ```json
   {
     "id": 1,
     "username": "emilys",
     "email": "emily.johnson@x.dummyjson.com",
     "firstName": "Emily",
     "lastName": "Johnson",
     "gender": "female",
     "image": "https://dummyjson.com/icon/emilys/128",
     "iat": 1794053415,
     "exp": 1794055215
   }
   ```
   `iat` (issued at) — время выдачи токена, `exp` (expiration) — время, когда он истекает (Unix-время в секундах).

3. **Signature (подпись)** — криптографическая подпись первых двух частей:
   ```
   HMACSHA256(base64url(header) + "." + base64url(payload), секретный_ключ)
   ```
   Секретный ключ знает только сервер. По подписи сервер проверяет, что токен выдал именно он и что в нём ничего не меняли. Если изменить хотя бы один символ в header или payload, подпись не совпадёт, и токен будет отклонён.

### 2. Почему в JWT нельзя хранить пароль

- **Payload не зашифрован**, он только закодирован в Base64URL. Любой, у кого есть токен, прочитает его содержимое за секунду: на jwt.io или командой `atob()` в консоли. Подпись защищает от **подделки**, но не от **чтения**.
- Токен много где «светится»: он лежит в `localStorage` (его может украсть скрипт при XSS-атаке), отправляется в каждом запросе, может попасть в логи сервера, прокси и инструменты отладки.
- Токен нельзя «отозвать» из чужих рук. Пароль, раз попав в токен, утёк бы навсегда. Украденный токен же перестаёт работать после `exp`.
- Пароль в токене и не нужен. Токен сам по себе доказывает, что пользователь уже вошёл, а пароль сервер проверяет один раз при входе и хранит у себя только в виде хэша.

Поэтому в payload кладут только неконфиденциальные данные: id, логин, роль, срок действия.

### 3. Чем access-токен отличается от refresh-токена

| | Access-токен | Refresh-токен |
|---|---|---|
| Зачем | Доступ к защищённым данным (`/auth/me` и т.п.) | Получение новой пары токенов (`/auth/refresh`) |
| Куда отправляется | В **каждый** запрос, в заголовке `Authorization: Bearer` | **Только** на эндпоинт обновления |
| Срок жизни | Короткий: минуты или час (у dummyjson по умолчанию 60 минут) | Длинный: дни или недели (у dummyjson 30 дней) |
| Если украдут | Злоумышленник получит доступ ненадолго, до `exp` | Опаснее, поэтому его отправляют реже и могут отзывать на сервере |

Схема работы: access-токен живёт недолго, поэтому даже его утечка не так страшна. Когда он истекает и сервер отвечает 401, приложение «тихо» обменивает refresh-токен на новую пару токенов, и пользователю не нужно заново вводить пароль. Если refresh-токен тоже недействителен, нужен повторный вход.

### 4. Что означает ответ 401

**401 Unauthorized** означает «сервер не знает, кто ты»: запрос не прошёл **аутентификацию**. Причины бывают такие:
- токена нет (dummyjson: `"Access Token is required"`);
- токен истёк, `exp` в прошлом (dummyjson: `"Token Expired!"`);
- токен повреждён или подделан, подпись не сошлась (dummyjson: `"Invalid/Expired Token!"`).

Что делать клиенту: попробовать обновить токен через refresh, а если не вышло, удалить токены и отправить пользователя на страницу входа.

Не путать с **403 Forbidden**: там сервер знает, кто ты, но **доступа к ресурсу у тебя нет** (не хватает прав). Например, dummyjson отвечает 403 на неверный refresh-токен.
